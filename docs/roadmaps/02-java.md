# Bloque 2: Java

Este bloque contiene 7 roadmaps independientes. Cada roadmap avanza en 30 pasos, desde cero hasta una evidencia de nivel avanzado; no presupone experiencia previa en el tema.

Los pasos 1–10 construyen fundamentos, 11–20 desarrollan práctica y diagnóstico, y 21–30 integran el tema en un resultado más cercano al trabajo profesional. Marca cada casilla solo cuando puedas mostrar la evidencia indicada.

## Tema 2: Java — Fundamentos

**Meta:** proyecto Java ejecutable con matriz de versiones y notas de compatibilidad

**Contexto de práctica:** compilar y ejecutar una orden logística en Java

**Conocimientos que conecta:** fundamentos de programación, Maven y Spring

### Pasos 1–10: nivel Principiante

- [ ] **Paso 1.** Describe el problema de industria «compilar y ejecutar una orden logística en Java» y quién recibe valor de resolverlo.
- [ ] **Paso 2.** Escribe el resultado experto observable: proyecto Java ejecutable con matriz de versiones y notas de compatibilidad.
- [ ] **Paso 3.** Enumera lo que ya sabes y los prerrequisitos mínimos para estudiar java — fundamentos.
- [ ] **Paso 4.** Define un glosario propio para las piezas de JDK/JRE/JVM, source-to-bytecode, main, classpath, packages, LTS 8/11/17/21, historia y Virtual Threads.
- [ ] **Paso 5.** Dibuja el modelo, flujo o sistema físico de JDK/JRE/JVM, source-to-bytecode, main, classpath, packages, LTS 8/11/17/21, historia y Virtual Threads antes de memorizar términos.
- [ ] **Paso 6.** Prepara JDK, jshell, javac y java; registra versión, comandos y una forma segura de limpiar el laboratorio.
- [ ] **Paso 7.** Encuentra en dev.java/learn y documentación de Oracle Java una explicación oficial y anota qué conceptos confirma.
- [ ] **Paso 8.** Traza un caso exitoso de «compilar y ejecutar una orden logística en Java» desde la entrada hasta el resultado.
- [ ] **Paso 9.** Resuelve «compilar con javac, inspeccionar bytecode y ejecutar la misma tarea en una versión LTS objetivo» con la solución más pequeña que funcione.
- [ ] **Paso 10.** Provoca el error «confundir JDK con JVM o asumir que todo Java moderno corre en Java 8» en un entorno desechable y captura la evidencia.

### Pasos 11–20: nivel Intermedio

- [ ] **Paso 11.** Diagnostica el fallo anterior paso a paso; explica causa, síntoma y corrección, sin ocultar el error.
- [ ] **Paso 12.** Implementa la pieza central de JDK/JRE/JVM, source-to-bytecode, main, classpath, packages, LTS 8/11/17/21, historia y Virtual Threads y sepárala de presentación/configuración cuando corresponda.

- [ ] **Paso 14.** Compara dos enfoques para «compilar y ejecutar una orden logística en Java» y registra un criterio medible para elegir.
- [ ] **Paso 15.** Especifica entradas, salidas, errores esperados y supuestos del componente de java — fundamentos.
- [ ] **Paso 16.** Revisa validación, permisos, datos sensibles, unidades o seguridad funcional pertinentes a JDK/JRE/JVM, source-to-bytecode, main, classpath, packages, LTS 8/11/17/21, historia y Virtual Threads.
- [ ] **Paso 17.** Introduce un fallo propio del dominio —por ejemplo entrada inválida, inconsistencia, pérdida de conexión o error de colaboración— y define cómo recuperarte.
- [ ] **Paso 18.** Mide una propiedad adecuada al problema —tiempo, calidad, error, consultas, recursos o esfuerzo— y conserva la línea base.
- [ ] **Paso 19.** Optimiza solo una limitación demostrada y compara la medición antes/después.
- [ ] **Paso 20.** Comprueba persistencia, reinicio, reproducibilidad o restauración del resultado «proyecto Java ejecutable con matriz de versiones y notas de compatibilidad».

### Pasos 21–30: nivel Avanzado

- [ ] **Paso 21.** Automatiza build, análisis o verificación del ejercicio para detectar regresiones al cambiarlo.
- [ ] **Paso 22.** Documenta una decisión técnica y enlaza evidencia primaria consultada en dev.java/learn y documentación de Oracle Java.
- [ ] **Paso 23.** Pide revisión a otra persona o usa una checklist; corrige un problema concreto de claridad o robustez.
- [ ] **Paso 24.** Completa un laboratorio autónomo que produzca «proyecto Java ejecutable con matriz de versiones y notas de compatibilidad» y guarda entrada, salida y pruebas.
- [ ] **Paso 25.** Evalúa el laboratorio contra criterios explícitos: corrección, casos límite, seguridad y evidencia.
- [ ] **Paso 26.** Conecta java — fundamentos con fundamentos de programación, Maven y Spring; dibuja el contrato entre ambos conocimientos.
- [ ] **Paso 27.** Diseña una parte del proyecto integrador para «compilar y ejecutar una orden logística en Java» y registra dependencias y riesgos.
- [ ] **Paso 28.** Construye esa parte, ejecuta las pruebas y registra qué no cubre el entorno de laboratorio.
- [ ] **Paso 29.** Amplía hacia el nivel avanzado con una restricción real: escala, concurrencia, tolerancia a fallos o incertidumbre.
- [ ] **Paso 30.** Explica el sistema sin notas, defiende una decisión con evidencia y enseña a otra persona a reproducir «proyecto Java ejecutable con matriz de versiones y notas de compatibilidad».

**Criterio de salida:** entrega «proyecto Java ejecutable con matriz de versiones y notas de compatibilidad», explica «confundir JDK con JVM o asumir que todo Java moderno corre en Java 8» y demuestra cómo java — fundamentos se conecta con fundamentos de programación, Maven y Spring.

**Fuentes primarias para iniciar:** dev.java/learn y documentación de Oracle Java.
