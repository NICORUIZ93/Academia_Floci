# Bloque 11: Frontend Angular

Este bloque contiene 2 roadmaps independientes. Cada roadmap avanza en 30 pasos, desde cero hasta una evidencia de nivel avanzado; no presupone experiencia previa en el tema.

Los pasos 1–10 construyen fundamentos, 11–20 desarrollan práctica y diagnóstico, y 21–30 integran el tema en un resultado más cercano al trabajo profesional. Marca cada casilla solo cuando puedas mostrar la evidencia indicada.

## Tema 33: Angular moderno y Angular 22

**Meta:** feature Angular con estados HTTP discriminados, pruebas y render medido

**Contexto de práctica:** construir un tablero de tracking reactivo que mantenga loading/data/error coherentes

**Conocimientos que conecta:** REST, accesibilidad y rendimiento

### Pasos 1–10: nivel Principiante

- [ ] **Paso 1.** Describe el problema de industria «construir un tablero de tracking reactivo que mantenga loading/data/error coherentes» y quién recibe valor de resolverlo.
- [ ] **Paso 2.** Escribe el resultado experto observable: feature Angular con estados HTTP discriminados, pruebas y render medido.
- [ ] **Paso 3.** Enumera lo que ya sabes y los prerrequisitos mínimos para estudiar angular moderno y angular 22.
- [ ] **Paso 4.** Define un glosario propio para las piezas de standalone, Signals/httpResource/computed/effect, OnPush, @if/@for, Signal Forms, Router, SSR y zoneless.
- [ ] **Paso 5.** Dibuja el modelo, flujo o sistema físico de standalone, Signals/httpResource/computed/effect, OnPush, @if/@for, Signal Forms, Router, SSR y zoneless antes de memorizar términos.
- [ ] **Paso 6.** Prepara Angular CLI y TypeScript, Angular CLI fijado a Angular 22 y docs versionadas, Angular DevTools y fixture de lista; registra versión, comandos y una forma segura de limpiar el laboratorio.
- [ ] **Paso 7.** Encuentra en angular.dev/essentials; angular.dev/guide/http y notas oficiales de Angular 22; angular.dev/best-practices/skipping-subtrees y guía oficial Angular 22 una explicación oficial y anota qué conceptos confirma.
- [ ] **Paso 8.** Traza un caso exitoso de «construir un tablero de tracking reactivo que mantenga loading/data/error coherentes» desde la entrada hasta el resultado.
- [ ] **Paso 9.** Resuelve «medir render, probar error/cancelación y validar navegación/formulario» con la solución más pequeña que funcione.
- [ ] **Paso 10.** Provoca el error «mezclar Angular 22 sin verificar APIs disponibles o derivar estado con effects» en un entorno desechable y captura la evidencia.

### Pasos 11–20: nivel Intermedio

- [ ] **Paso 11.** Diagnostica el fallo anterior paso a paso; explica causa, síntoma y corrección, sin ocultar el error.
- [ ] **Paso 12.** Implementa la pieza central de standalone, Signals/httpResource/computed/effect, OnPush, @if/@for, Signal Forms, Router, SSR y zoneless y sepárala de presentación/configuración cuando corresponda.
- [ ] **Paso 13.** Añade pruebas para caso normal, borde, entrada inválida y una regresión del fallo provocado.
- [ ] **Paso 14.** Compara dos enfoques para «construir un tablero de tracking reactivo que mantenga loading/data/error coherentes» y registra un criterio medible para elegir.
- [ ] **Paso 15.** Especifica entradas, salidas, errores esperados y supuestos del componente de angular moderno y angular 22.
- [ ] **Paso 16.** Revisa validación, permisos, datos sensibles, unidades o seguridad funcional pertinentes a standalone, Signals/httpResource/computed/effect, OnPush, @if/@for, Signal Forms, Router, SSR y zoneless.
- [ ] **Paso 17.** Introduce un fallo propio del dominio —por ejemplo entrada inválida, inconsistencia, pérdida de conexión o error de colaboración— y define cómo recuperarte.
- [ ] **Paso 18.** Mide una propiedad adecuada al problema —tiempo, calidad, error, consultas, recursos o esfuerzo— y conserva la línea base.
- [ ] **Paso 19.** Optimiza solo una limitación demostrada y compara la medición antes/después.
- [ ] **Paso 20.** Comprueba persistencia, reinicio, reproducibilidad o restauración del resultado «feature Angular con estados HTTP discriminados, pruebas y render medido».

### Pasos 21–30: nivel Avanzado

- [ ] **Paso 21.** Automatiza build, análisis o verificación del ejercicio para detectar regresiones al cambiarlo.
- [ ] **Paso 22.** Documenta una decisión técnica y enlaza evidencia primaria consultada en angular.dev/essentials; angular.dev/guide/http y notas oficiales de Angular 22; angular.dev/best-practices/skipping-subtrees y guía oficial Angular 22.
- [ ] **Paso 23.** Pide revisión a otra persona o usa una checklist; corrige un problema concreto de claridad o robustez.
- [ ] **Paso 24.** Completa un laboratorio autónomo que produzca «feature Angular con estados HTTP discriminados, pruebas y render medido» y guarda entrada, salida y pruebas.
- [ ] **Paso 25.** Evalúa el laboratorio contra criterios explícitos: corrección, casos límite, seguridad y evidencia.
- [ ] **Paso 26.** Conecta angular moderno y angular 22 con REST, accesibilidad y rendimiento; dibuja el contrato entre ambos conocimientos.
- [ ] **Paso 27.** Diseña una parte del proyecto integrador para «construir un tablero de tracking reactivo que mantenga loading/data/error coherentes» y registra dependencias y riesgos.
- [ ] **Paso 28.** Construye esa parte, ejecuta las pruebas y registra qué no cubre el entorno de laboratorio.
- [ ] **Paso 29.** Amplía hacia el nivel avanzado con una restricción real: escala, concurrencia, tolerancia a fallos o incertidumbre.
- [ ] **Paso 30.** Explica el sistema sin notas, defiende una decisión con evidencia y enseña a otra persona a reproducir «feature Angular con estados HTTP discriminados, pruebas y render medido».

**Criterio de salida:** entrega «feature Angular con estados HTTP discriminados, pruebas y render medido», explica «mezclar Angular 22 sin verificar APIs disponibles o derivar estado con effects» y demuestra cómo angular moderno y angular 22 se conecta con REST, accesibilidad y rendimiento.

**Fuentes primarias para iniciar:** angular.dev/essentials; angular.dev/guide/http y notas oficiales de Angular 22; angular.dev/best-practices/skipping-subtrees y guía oficial Angular 22.
