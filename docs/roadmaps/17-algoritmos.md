# Bloque 17: Algoritmos y estructuras de datos

Este bloque contiene 1 roadmaps independientes. Cada roadmap avanza en 30 pasos, desde cero hasta una evidencia de nivel avanzado; no presupone experiencia previa en el tema.

Los pasos 1–10 construyen fundamentos, 11–20 desarrollan práctica y diagnóstico, y 21–30 integran el tema en un resultado más cercano al trabajo profesional. Marca cada casilla solo cuando puedas mostrar la evidencia indicada.

## Tema 50: Algoritmos y estructuras de datos

**Meta:** suite comparativa con grafos de prueba, correctitud y rendimiento

**Contexto de práctica:** calcular una ruta para repartidores y justificar coste frente a tamaño del grafo

**Conocimientos que conecta:** colecciones Java, mapas, persistencia y logística

### Pasos 1–10: nivel Principiante

- [ ] **Paso 1.** Describe el problema de industria «calcular una ruta para repartidores y justificar coste frente a tamaño del grafo» y quién recibe valor de resolverlo.
- [ ] **Paso 2.** Escribe el resultado experto observable: suite comparativa con grafos de prueba, correctitud y rendimiento.
- [ ] **Paso 3.** Enumera lo que ya sabes y los prerrequisitos mínimos para estudiar algoritmos y estructuras de datos.
- [ ] **Paso 4.** Define un glosario propio para las piezas de Big-O, búsqueda/ordenamiento, BFS/DFS, Dijkstra, hash/tree/graph y dynamic programming.
- [ ] **Paso 5.** Dibuja el modelo, flujo o sistema físico de Big-O, búsqueda/ordenamiento, BFS/DFS, Dijkstra, hash/tree/graph y dynamic programming antes de memorizar términos.
- [ ] **Paso 6.** Prepara Python, pytest y profiler; registra versión, comandos y una forma segura de limpiar el laboratorio.
- [ ] **Paso 7.** Encuentra en visualgo.net y Python docs una explicación oficial y anota qué conceptos confirma.
- [ ] **Paso 8.** Traza un caso exitoso de «calcular una ruta para repartidores y justificar coste frente a tamaño del grafo» desde la entrada hasta el resultado.
- [ ] **Paso 9.** Resuelve «implementar y visualizar búsqueda, ordenamiento y Dijkstra con casos y métricas» con la solución más pequeña que funcione.
- [ ] **Paso 10.** Provoca el error «usar Dijkstra con pesos negativos o medir complejidad solo con un ejemplo pequeño» en un entorno desechable y captura la evidencia.

### Pasos 11–20: nivel Intermedio

- [ ] **Paso 12.** Implementa la pieza central de Big-O, búsqueda/ordenamiento, BFS/DFS, Dijkstra, hash/tree/graph y dynamic programming y sepárala de presentación/configuración cuando corresponda.

- [ ] **Paso 14.** Compara dos enfoques para «calcular una ruta para repartidores y justificar coste frente a tamaño del grafo» y registra un criterio medible para elegir.
- [ ] **Paso 15.** Especifica entradas, salidas, errores esperados y supuestos del componente de algoritmos y estructuras de datos.
- [ ] **Paso 16.** Revisa validación, permisos, datos sensibles, unidades o seguridad funcional pertinentes a Big-O, búsqueda/ordenamiento, BFS/DFS, Dijkstra, hash/tree/graph y dynamic programming.
- [ ] **Paso 17.** Introduce un fallo propio del dominio —por ejemplo entrada inválida, inconsistencia, pérdida de conexión o error de colaboración— y define cómo recuperarte.
- [ ] **Paso 18.** Mide una propiedad adecuada al problema —tiempo, calidad, error, consultas, recursos o esfuerzo— y conserva la línea base.

### Pasos 21–30: nivel Avanzado

- [ ] **Paso 21.** Automatiza build, análisis o verificación del ejercicio para detectar regresiones al cambiarlo.
- [ ] **Paso 22.** Documenta una decisión técnica y enlaza evidencia primaria consultada en visualgo.net y Python docs.
- [ ] **Paso 23.** Pide revisión a otra persona o usa una checklist; corrige un problema concreto de claridad o robustez.

- [ ] **Paso 25.** Evalúa el laboratorio contra criterios explícitos: corrección, casos límite, seguridad y evidencia.
