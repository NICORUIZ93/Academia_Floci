# S3

**Protocolo:** REST XML
**Punto final:** `http://localhost:4566/{bucket}/{key}`

## Operaciones compatibles

| Categoría | Operaciones |
|---|---|
| **Cubos** | ListBuckets, CreateBucket, HeadBucket, DeleteBucket, GetBucketLocation |
| **Objetos** | PutObject, GetObject, GetObjectAttributes, HeadObject, DeleteObject, DeleteObjects, CopyObject |
| **Listado** | ListObjects, ListObjectsV2, ListObjectVersions |
| **Multiparte** | CreateMultipartUpload, UploadPart, CompleteMultipartUpload, AbortMultipartUpload, ListMultipartUploads |
| **Versionamiento** | PutBucketVersioning, GetBucketVersioning |
| **Etiquetado** | PutBucketTagging, GetBucketTagging, PutObjectTagging, GetObjectTagging, DeleteObjectTagging |
| **Política** | PutBucketPolicy, GetBucketPolicy, DeleteBucketPolicy |
| **CORS** | PutBucketCors, GetBucketCors, DeleteBucketCors |
| **Ciclo de vida** | PutBucketLifecycle, GetBucketLifecycle, DeleteBucketLifecycle |
| **ACL** | PutBucketAcl, GetBucketAcl, PutObjectAcl, GetObjectAcl |
| **Cifrado** | PutBucketEncryption, GetBucketEncryption, DeleteBucketEncryption |
| **Notificaciones** | PutBucketNotification, GetBucketNotification |
| **Bloqueo de objetos** | PutObjectLockConfiguration, GetObjectLockConfiguration, PutObjectRetention, GetObjectRetention, PutObjectLegalHold, GetObjectLegalHold |
| **URL prefirmadas** | Genera y valida URL GET/PUT prefirmadas |
| **S3 Select** | SelectObjectContent |
| **Bloque de acceso público** | PutPublicAccessBlock, GetPublicAccessBlock, DeletePublicAccessBlock |

**RestoreObject** se acepta pero se descarta: Floci valida la solicitud y devuelve `202 Accepted`, pero no se ejecuta ninguna máquina de estado de restauración.

## Lecturas de rango

`GetObject` admite solicitudes estándar `Range: bytes=`. Las respuestas parciales devuelven `206`, `Content-Range`, `Content-Length`, `Accept-Ranges: bytes` y metadatos de objetos. Los encabezados de suma de comprobación de todo el objeto se omiten en las respuestas de rango porque la suma de comprobación almacenada cubre el objeto completo, no el segmento de bytes devuelto. Las lecturas de objetos completos y de rango transmiten bytes de objetos desde el almacenamiento en lugar de materializar primero el cuerpo de la respuesta.

Los rangos de sufijos contra objetos vacíos devuelven una respuesta `200` vacía, que coincide con el comportamiento de AWS utilizado por los clientes que emiten lecturas finales.

## S3 Select

`SelectObjectContent` ejecuta consultas SQL directamente contra objetos S3 sin descargar el archivo completo. Floci admite líneas CSV, JSON, matrices JSON y entradas Parquet. El dialecto SQL sigue la [referencia AWS S3 Select SQL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-select-sql-reference.html).

### Modos de ejecución

Floci elige el motor de ejecución automáticamente según el formato de entrada y si el sidecar [floci-duck](https://hub.docker.com/r/floci/floci-duck) se está ejecutando:

| Condición | Motor | Notas |
|---|---|---|
| La entrada es Parquet | floci-duck (obligatorio) | `read_parquet` de DuckDB: el sidecar debe estar disponible |
| La entrada es CSV con `FileHeaderInfo=USE` y floci-duck en ejecución | floci-duck | DuckDB SQL completo: todos los operadores, LIKE, BETWEEN, IN, IS NULL, AND/OR/NOT |
| La entrada es JSON y floci-duck se está ejecutando | floci-duck | `read_json_auto`: admite líneas JSON y arreglos JSON |
| La entrada es CSV con `FileHeaderInfo=NONE` o `IGNORE`, o floci-duck no se está ejecutando | Evaluador Java | Soporta SELECT*, proyección de columna, WHERE simple con =, !=, <, >, <=, >=, LIKE, BETWEEN, IN, IS NULL, AND/OR/NOT, LIMIT |

El sidecar floci-duck comienza lentamente en la **primera consulta Athena**. Hasta entonces, `isAvailable()` devuelve falso y S3 Select recurre al evaluador Java para CSV y JSON. Una vez que el sidecar está en ejecución, las llamadas posteriores a S3 Select se enrutan automáticamente a través de DuckDB.

Si floci-duck no se está ejecutando y el objeto es Parquet, S3 Select devuelve un error: la decodificación de Parquet requiere DuckDB.

### Modos FileHeaderInfo (CSV)

| Valor | Comportamiento |
|---|---|
| `USE` | La primera fila es el encabezado; los nombres de las columnas están disponibles en WHERE y SELECT |
| `IGNORE` | La primera fila se omite y no se incluye en el resultado; sólo funcionan las referencias posicionales `_N` |
| `NONE` | Todas las filas son datos; solo funcionan las referencias posicionales `_N` (por ejemplo, `WHERE _1 = 'Alice'`) |

### Operadores compatibles con SQL

Cuando se utiliza el evaluador Java (sin floci-duck o CSV con `FileHeaderInfo=NONE/IGNORE`):

- Comparación: `=`, `!=`, `<>`, `<`, `>`, `<=`, `>=`
- Coincidencia de patrones: `LIKE` (admite comodines `%` y `_`)
- Gama: `BETWEEN ... AND ...`
- Establecer membresía: `IN (...)`
- Comprobaciones nulas: `IS NULL`, `IS NOT NULL`
- Lógico: `AND`, `OR`, `NOT`
- Cláusulas: `SELECT *`, proyección de columna, `LIMIT`

### Formatos de salida

S3 Select admite salida de formato cruzado: un objeto CSV puede producir salida JSON y viceversa.

| Entrada | Salida | Formato |
|---|---|---|
| CSV | CSV | Predeterminado: valores separados por comas |
| CSV | JSON | Un objeto JSON por fila: `{"col1":"val1","col2":"val2"}` |
| JSON | JSON | Predeterminado: un objeto JSON por línea |
| JSON | CSV | Valores separados por comas, valores citados cuando contienen comas o nuevas líneas |

### Ejemplo

```bash
export AWS_ENDPOINT_URL=http://localhost:4566

# Upload a CSV file
printf 'name,age,city\nAlice,30,New York\nBob,25,\nCharlie,35,London\n' \
  | aws s3 cp - s3://my-bucket/people.csv

# Query with WHERE and column projection
aws s3api select-object-content \
  --bucket my-bucket \
  --key people.csv \
  --expression "SELECT name, city FROM S3Object WHERE age >= 30" \
  --expression-type SQL \
  --input-serialization '{"CSV":{"FileHeaderInfo":"USE"}}' \
  --output-serialization '{"CSV":{}}' \
  /dev/stdout

# IS NULL check
aws s3api select-object-content \
  --bucket my-bucket \
  --key people.csv \
  --expression "SELECT name FROM S3Object WHERE city IS NULL" \
  --expression-type SQL \
  --input-serialization '{"CSV":{"FileHeaderInfo":"USE"}}' \
  --output-serialization '{"CSV":{}}' \
  /dev/stdout

# JSON Lines input
printf '{"name":"Alice","score":95}\n{"name":"Bob","score":72}\n' \
  | aws s3 cp - s3://my-bucket/scores.json

aws s3api select-object-content \
  --bucket my-bucket \
  --key scores.json \
  --expression "SELECT * FROM S3Object WHERE score > 80" \
  --expression-type SQL \
  --input-serialization '{"JSON":{"Type":"LINES"}}' \
  --output-serialization '{"JSON":{}}' \
  /dev/stdout
```

### Nota sobre el modo simulado

Cuando se configura `FLOCI_SERVICES_ATHENA_MOCK=true`, las consultas Athena se bloquean pero floci-duck **no** se inicia. En esa configuración, S3 Select utiliza el evaluador Java para CSV y JSON. Las consultas de Parquet fallarán a menos que `FLOCI_SERVICES_DUCK_URL` apunte a una instancia de floci-duck que ya se esté ejecutando.

## No implementado

Estas características de AWS S3 no tienen controlador en Floci. Las llamadas devolverán un error (normalmente estilo `404` o `NoSuchBucket`):

- Replicación (`PutBucketReplication`, `GetBucketReplication`, `DeleteBucketReplication`)
- Alojamiento de sitios web (`PutBucketWebsite`, `GetBucketWebsite`, `DeleteBucketWebsite`)
- Registro de acceso (`PutBucketLogging`, `GetBucketLogging`)
- Solicitar pago (`PutBucketRequestPayment`, `GetBucketRequestPayment`)
- Configuraciones de niveles inteligentes
- Configuraciones de inventario
- Configuraciones de métricas y análisis.

## Configuración

| Variables | Predeterminado | Descripción |
|---|---|---|
| `FLOCI_SERVICES_S3_ENABLED` | `true` | Activar o desactivar el servicio |
| `FLOCI_SERVICES_S3_DEFAULT_PRESIGN_EXPIRY_SECONDS` | `3600` | Caducidad de URL prefirmada predeterminada (1 hora) |
| `FLOCI_AUTH_PRESIGN_SECRET` | `local-emulator-secret` | Secreto utilizado para firmar URL prefirmadas |

## Ejemplos

```bash
export AWS_ENDPOINT_URL=http://localhost:4566

# Create bucket
aws s3 mb s3://my-bucket --endpoint-url $AWS_ENDPOINT_URL

# Upload a file
aws s3 cp ./report.pdf s3://my-bucket/reports/report.pdf --endpoint-url $AWS_ENDPOINT_URL

# Upload inline content
echo '{"hello":"world"}' | aws s3 cp - s3://my-bucket/data.json --endpoint-url $AWS_ENDPOINT_URL

# Download
aws s3 cp s3://my-bucket/data.json ./data.json --endpoint-url $AWS_ENDPOINT_URL

# Inspect object attributes without downloading the body
aws s3api get-object-attributes \
  --bucket my-bucket \
  --key data.json \
  --object-attributes ETag ObjectSize StorageClass \
  --endpoint-url $AWS_ENDPOINT_URL

# List
aws s3 ls s3://my-bucket --endpoint-url $AWS_ENDPOINT_URL

# Delete
aws s3 rm s3://my-bucket/data.json --endpoint-url $AWS_ENDPOINT_URL

# Enable versioning
aws s3api put-bucket-versioning \
  --bucket my-bucket \
  --versioning-configuration Status=Enabled \
  --endpoint-url $AWS_ENDPOINT_URL

# Generate a pre-signed URL (valid for 1 hour)
aws s3 presign s3://my-bucket/report.pdf \
  --expires-in 3600 \
  --endpoint-url $AWS_ENDPOINT_URL
```

## Estilos de direccionamiento

Floci admite el direccionamiento S3 con **estilo de ruta** y **estilo de alojamiento virtual**.

### Path-Style (siempre funciona)

El estilo de ruta incorpora el nombre del depósito en la ruta URL:

```
http://localhost:4566/my-bucket/my-key
```

Habilítelo en SDK con `forcePathStyle` / `pathStyleAccessEnabled`:

=== "Java"

    ```java
    S3Client s3 = S3Client.builder()
        .endpointOverride(URI.create("http://localhost:4566"))
        .forcePathStyle(true)
        .build();
    ```

=== "Node.js"

    ```javascript
    const s3 = new S3Client({
      endpoint: "http://localhost:4566",
      forcePathStyle: true,
    });
    ```

=== "Python"

    ```python
    s3 = boto3.client("s3",
        endpoint_url="http://localhost:4566",
        config=Config(s3={"addressing_style": "path"}))
    ```

### Estilo alojado virtual

El estilo de alojamiento virtual coloca el nombre del depósito en el nombre del host:

```
http://my-bucket.s3.localhost.floci.io:4566/my-key
```

Floci admite esto de forma nativa; no se necesita `forcePathStyle`. Los siguientes dominios DNS comodín se resuelven en `127.0.0.1` a través de DNS público, por lo que las solicitudes alojadas virtualmente llegan automáticamente a Floci en la máquina host:

| Patrón de dominio | Resuelve |
|---|---|
| `*.localhost.floci.io` | `127.0.0.1` |
| `*.s3.localhost.floci.io` | `127.0.0.1` |
| `*.localhost.localstack.cloud` | `127.0.0.1` |
| `*.s3.localhost.localstack.cloud` | `127.0.0.1` |

El `http://localhost:4566` simple también funciona sin `forcePathStyle`: el SDK envía `Host: my-bucket.localhost:4566` y el filtro de Floci extrae el nombre del depósito de ese encabezado.

Configure el punto final SDK en uno de los dominios base (sin `forcePathStyle`):

=== "Java"

    ```java
    S3Client s3 = S3Client.builder()
        .endpointOverride(URI.create("http://s3.localhost.floci.io:4566"))
        .region(Region.US_EAST_1)
        .credentialsProvider(StaticCredentialsProvider.create(
            AwsBasicCredentials.create("test", "test")))
        .build();
    // SDK sends requests to: my-bucket.s3.localhost.floci.io:4566
    ```

=== "Node.js"

    ```javascript
    const s3 = new S3Client({
      endpoint: "http://s3.localhost.floci.io:4566",
      // no forcePathStyle — SDK uses virtual-hosted style by default
    });
    // SDK sends requests to: my-bucket.s3.localhost.floci.io:4566
    ```

=== "Python"

    ```python
    s3 = boto3.client("s3",
        endpoint_url="http://s3.localhost.floci.io:4566")
    # SDK sends requests to: my-bucket.s3.localhost.floci.io:4566
    ```

#### Estilo alojado virtual dentro de Docker

Dentro de los contenedores Docker, `127.0.0.1` se resuelve en el contenedor mismo, no en Floci. El **servidor DNS integrado** de Floci maneja esto automáticamente: resuelve `*.localhost.floci.io`, `*.s3.localhost.floci.io`, `*.localhost.localstack.cloud` y `*.s3.localhost.localstack.cloud` en la IP del contenedor de Floci en la red Docker.

Para usar el estilo de alojamiento virtual desde un contenedor de prueba, apunte su DNS a Floci y establezca el punto final en el nombre de host del servicio de Floci:

```bash
FLOCI_IP=$(docker inspect -f '{{.NetworkSettings.Networks.floci_default.IPAddress}}' floci)

docker run --rm \
  --network floci_default \
  --dns "$FLOCI_IP" \
  -e FLOCI_ENDPOINT=http://floci:4566 \
  -e FLOCI_S3_VHOST_ENDPOINT=http://floci:4566 \
  my-test-image
```

Con `FLOCI_HOSTNAME=floci` configurado en el contenedor Floci (predeterminado en el `docker-compose.yml` proporcionado), el DNS integrado resuelve `my-bucket.floci` en la IP de Floci y `S3VirtualHostFilter` extrae el nombre del depósito del encabezado del host.

## Notas de atributos de objeto

Floci ahora persiste y devuelve el siguiente estado de atributo de objeto en las API de objeto S3:

- metadatos de usuario de `x-amz-meta-*`
- clase de almacenamiento de `x-amz-storage-class`
- metadatos de suma de comprobación para lecturas de objetos y `GetObjectAttributes`
- manifiestos de piezas de varias partes para `GetObjectAttributes(ObjectParts)`
- ACL de objetos almacenados de `x-amz-acl` en `PutObject`, `CopyObject` e iniciación multiparte
- encabezados SSE de objetos explícitos de `x-amz-server-side-encryption` en `PutObject`, `CopyObject` e iniciación multiparte, reproducidos en `GetObject` y `HeadObject`

Limitaciones actuales:

- las respuestas de suma de verificación se centran en SHA-1 y SHA-256
- Las actualizaciones de metadatos basadas en copias admiten `x-amz-metadata-directive: REPLACE` para metadatos de usuario y tipo de contenido, pero aún no cubren todos los encabezados de copia de AWS.
- Los encabezados de concesión de ACL explícitos, como `x-amz-grant-read` y `x-amz-grant-full-control`, aún no están modelados.
- Las variantes de ACL predefinidas entre cuentas colapsan en el único propietario sintético del emulador donde Floci no modela un segundo principal distinto
- Se acepta `aws-exec-read` por compatibilidad, pero Floci aún no modela un beneficiario de lector de paquete EC2 distinto en `GetObjectAcl`.
