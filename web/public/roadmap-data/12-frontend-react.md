# Bloque 12: Frontend React

Este bloque contiene 1 roadmaps independientes. Cada roadmap avanza en 30 pasos, desde cero hasta una evidencia de nivel avanzado; no presupone experiencia previa en el tema.

Los pasos 1–10 construyen fundamentos, 11–20 desarrollan práctica y diagnóstico, y 21–30 integran el tema en un resultado más cercano al trabajo profesional. Marca cada casilla solo cuando puedas mostrar la evidencia indicada.

## Tema 35: React y Next.js

**Meta:** página con límites server/client y estrategia SSR/SSG justificada

**Contexto de práctica:** renderizar una página pública de tracking y una vista de cliente

**Conocimientos que conecta:** APIs, estado, accesibilidad y despliegue

### Pasos 1–10: nivel Principiante

- [ ] **Paso 1.** Describe el problema de industria «renderizar una página pública de tracking y una vista de cliente» y quién recibe valor de resolverlo.
- [ ] **Paso 2.** Escribe el resultado experto observable: página con límites server/client y estrategia SSR/SSG justificada.
- [ ] **Paso 3.** Enumera lo que ya sabes y los prerrequisitos mínimos para estudiar react y next.js.
- [ ] **Paso 4.** Define un glosario propio para las piezas de componentes, hooks, estado, Context, hooks propios, fetching, SSR/SSG/ISR y App Router.
- [ ] **Paso 5.** Dibuja el modelo, flujo o sistema físico de componentes, hooks, estado, Context, hooks propios, fetching, SSR/SSG/ISR y App Router antes de memorizar términos.
- [ ] **Paso 6.** Prepara React y Next.js con versiones fijadas; registra versión, comandos y una forma segura de limpiar el laboratorio.
- [ ] **Paso 7.** Encuentra en react.dev/learn y nextjs.org/docs una explicación oficial y anota qué conceptos confirma.
- [ ] **Paso 8.** Traza un caso exitoso de «renderizar una página pública de tracking y una vista de cliente» desde la entrada hasta el resultado.
- [ ] **Paso 9.** Resuelve «trazar render y fetching en server/client y medir hydration» con la solución más pequeña que funcione.
- [ ] **Paso 10.** Provoca el error «llamar a hooks condicionalmente o compartir datos sensibles en HTML público» en un entorno desechable y captura la evidencia.

### Pasos 11–20: nivel Intermedio

- [ ] **Paso 11.** Diagnostica el fallo anterior paso a paso; explica causa, síntoma y corrección, sin ocultar el error.
- [ ] **Paso 12.** Implementa la pieza central de componentes, hooks, estado, Context, hooks propios, fetching, SSR/SSG/ISR y App Router y sepárala de presentación/configuración cuando corresponda.
- [ ] **Paso 13.** Añade pruebas para caso normal, borde, entrada inválida y una regresión del fallo provocado.
- [ ] **Paso 14.** Compara dos enfoques para «renderizar una página pública de tracking y una vista de cliente» y registra un criterio medible para elegir.
- [ ] **Paso 15.** Especifica entradas, salidas, errores esperados y supuestos del componente de react y next.js.
- [ ] **Paso 16.** Revisa validación, permisos, datos sensibles, unidades o seguridad funcional pertinentes a componentes, hooks, estado, Context, hooks propios, fetching, SSR/SSG/ISR y App Router.
- [ ] **Paso 17.** Introduce un fallo propio del dominio —por ejemplo entrada inválida, inconsistencia, pérdida de conexión o error de colaboración— y define cómo recuperarte.
- [ ] **Paso 18.** Mide una propiedad adecuada al problema —tiempo, calidad, error, consultas, recursos o esfuerzo— y conserva la línea base.
- [ ] **Paso 19.** Optimiza solo una limitación demostrada y compara la medición antes/después.
- [ ] **Paso 20.** Comprueba persistencia, reinicio, reproducibilidad o restauración del resultado «página con límites server/client y estrategia SSR/SSG justificada».

### Pasos 21–30: nivel Avanzado

- [ ] **Paso 21.** Automatiza build, análisis o verificación del ejercicio para detectar regresiones al cambiarlo.
- [ ] **Paso 22.** Documenta una decisión técnica y enlaza evidencia primaria consultada en react.dev/learn y nextjs.org/docs.
- [ ] **Paso 23.** Pide revisión a otra persona o usa una checklist; corrige un problema concreto de claridad o robustez.
- [ ] **Paso 24.** Completa un laboratorio autónomo que produzca «página con límites server/client y estrategia SSR/SSG justificada» y guarda entrada, salida y pruebas.
- [ ] **Paso 25.** Evalúa el laboratorio contra criterios explícitos: corrección, casos límite, seguridad y evidencia.
- [ ] **Paso 26.** Conecta react y next.js con APIs, estado, accesibilidad y despliegue; dibuja el contrato entre ambos conocimientos.
- [ ] **Paso 27.** Diseña una parte del proyecto integrador para «renderizar una página pública de tracking y una vista de cliente» y registra dependencias y riesgos.
- [ ] **Paso 28.** Construye esa parte, ejecuta las pruebas y registra qué no cubre el entorno de laboratorio.
- [ ] **Paso 29.** Amplía hacia el nivel avanzado con una restricción real: escala, concurrencia, tolerancia a fallos o incertidumbre.
- [ ] **Paso 30.** Explica el sistema sin notas, defiende una decisión con evidencia y enseña a otra persona a reproducir «página con límites server/client y estrategia SSR/SSG justificada».

**Criterio de salida:** entrega «página con límites server/client y estrategia SSR/SSG justificada», explica «llamar a hooks condicionalmente o compartir datos sensibles en HTML público» y demuestra cómo react y next.js se conecta con APIs, estado, accesibilidad y despliegue.
