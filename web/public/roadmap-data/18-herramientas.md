# Bloque 18: Herramientas de desarrollo

Este bloque contiene 1 roadmaps independientes. Cada roadmap avanza en 30 pasos, desde cero hasta una evidencia de nivel avanzado; no presupone experiencia previa en el tema.

Los pasos 1–10 construyen fundamentos, 11–20 desarrollan práctica y diagnóstico, y 21–30 integran el tema en un resultado más cercano al trabajo profesional. Marca cada casilla solo cuando puedas mostrar la evidencia indicada.

## Tema 51: Herramientas de desarrollo

**Meta:** perfil editor documentado, ejercicios fechados y escena renderizada con versión fijada

**Contexto de práctica:** elegir y usar herramientas sin ejecutar cambios irreversibles a ciegas

**Conocimientos que conecta:** Git, práctica deliberada, algoritmos y documentación

### Pasos 1–10: nivel Principiante

- [ ] **Paso 1.** Describe el problema de industria «elegir y usar herramientas sin ejecutar cambios irreversibles a ciegas» y quién recibe valor de resolverlo.
- [ ] **Paso 2.** Escribe el resultado experto observable: perfil editor documentado, ejercicios fechados y escena renderizada con versión fijada.
- [ ] **Paso 3.** Enumera lo que ya sabes y los prerrequisitos mínimos para estudiar herramientas de desarrollo.
- [ ] **Paso 4.** Define un glosario propio para las piezas de VS Code, WinUtil, Manim/ManimGX, Exercism, CodeCademy/Codedden* y QuickRef.
- [ ] **Paso 5.** Dibuja el modelo, flujo o sistema físico de VS Code, WinUtil, Manim/ManimGX, Exercism, CodeCademy/Codedden* y QuickRef antes de memorizar términos.
- [ ] **Paso 6.** Prepara VS Code y un repositorio sandbox, WinUtil oficial en VM o máquina de prueba respaldada, Python compatible y Manim CE o ManimGX según versión; registra versión, comandos y una forma segura de limpiar el laboratorio.
- [ ] **Paso 7.** Encuentra en code.visualstudio.com/docs; exercism.org; docs.manim.community; revisar nombre y disponibilidad de plataforma citada una explicación oficial y anota qué conceptos confirma.
- [ ] **Paso 8.** Traza un caso exitoso de «elegir y usar herramientas sin ejecutar cambios irreversibles a ciegas» desde la entrada hasta el resultado.
- [ ] **Paso 9.** Resuelve «resolver un ejercicio en plataforma, generar un quick reference y renderizar una visualización tras verificar la API» con la solución más pequeña que funcione.
- [ ] **Paso 10.** Provoca el error «confiar en nombre dudoso de producto o ejecutar herramienta elevada sin revisar cambios» en un entorno desechable y captura la evidencia.

### Pasos 11–20: nivel Intermedio

- [ ] **Paso 11.** Diagnostica el fallo anterior paso a paso; explica causa, síntoma y corrección, sin ocultar el error.
- [ ] **Paso 12.** Implementa la pieza central de VS Code, WinUtil, Manim/ManimGX, Exercism, CodeCademy/Codedden* y QuickRef y sepárala de presentación/configuración cuando corresponda.
- [ ] **Paso 13.** Añade pruebas para caso normal, borde, entrada inválida y una regresión del fallo provocado.
- [ ] **Paso 14.** Compara dos enfoques para «elegir y usar herramientas sin ejecutar cambios irreversibles a ciegas» y registra un criterio medible para elegir.
- [ ] **Paso 15.** Especifica entradas, salidas, errores esperados y supuestos del componente de herramientas de desarrollo.
- [ ] **Paso 16.** Revisa validación, permisos, datos sensibles, unidades o seguridad funcional pertinentes a VS Code, WinUtil, Manim/ManimGX, Exercism, CodeCademy/Codedden* y QuickRef.
- [ ] **Paso 17.** Introduce un fallo propio del dominio —por ejemplo entrada inválida, inconsistencia, pérdida de conexión o error de colaboración— y define cómo recuperarte.
- [ ] **Paso 18.** Mide una propiedad adecuada al problema —tiempo, calidad, error, consultas, recursos o esfuerzo— y conserva la línea base.
- [ ] **Paso 19.** Optimiza solo una limitación demostrada y compara la medición antes/después.
- [ ] **Paso 20.** Comprueba persistencia, reinicio, reproducibilidad o restauración del resultado «perfil editor documentado, ejercicios fechados y escena renderizada con versión fijada».

### Pasos 21–30: nivel Avanzado

- [ ] **Paso 21.** Automatiza build, análisis o verificación del ejercicio para detectar regresiones al cambiarlo.
- [ ] **Paso 22.** Documenta una decisión técnica y enlaza evidencia primaria consultada en code.visualstudio.com/docs; exercism.org; docs.manim.community; revisar nombre y disponibilidad de plataforma citada.
- [ ] **Paso 23.** Pide revisión a otra persona o usa una checklist; corrige un problema concreto de claridad o robustez.
- [ ] **Paso 24.** Completa un laboratorio autónomo que produzca «perfil editor documentado, ejercicios fechados y escena renderizada con versión fijada» y guarda entrada, salida y pruebas.
- [ ] **Paso 25.** Evalúa el laboratorio contra criterios explícitos: corrección, casos límite, seguridad y evidencia.
- [ ] **Paso 26.** Conecta herramientas de desarrollo con Git, práctica deliberada, algoritmos y documentación; dibuja el contrato entre ambos conocimientos.
- [ ] **Paso 27.** Diseña una parte del proyecto integrador para «elegir y usar herramientas sin ejecutar cambios irreversibles a ciegas» y registra dependencias y riesgos.
- [ ] **Paso 28.** Construye esa parte, ejecuta las pruebas y registra qué no cubre el entorno de laboratorio.
- [ ] **Paso 29.** Amplía hacia el nivel avanzado con una restricción real: escala, concurrencia, tolerancia a fallos o incertidumbre.
- [ ] **Paso 30.** Explica el sistema sin notas, defiende una decisión con evidencia y enseña a otra persona a reproducir «perfil editor documentado, ejercicios fechados y escena renderizada con versión fijada».

**Criterio de salida:** entrega «perfil editor documentado, ejercicios fechados y escena renderizada con versión fijada», explica «confiar en nombre dudoso de producto o ejecutar herramienta elevada sin revisar cambios» y demuestra cómo herramientas de desarrollo se conecta con Git, práctica deliberada, algoritmos y documentación.

**Fuentes primarias para iniciar:** code.visualstudio.com/docs; exercism.org; docs.manim.community; revisar nombre y disponibilidad de plataforma citada.
